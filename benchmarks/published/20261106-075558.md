## Daemon: crashes, moves, idling

Two daemons with separate roots and caches stand in for two machines. Crash: an agent writes a file every 20 ms, the daemon is killed with SIGKILL, and a new one mounts the branch again. Synced: 64 writers append and `fsync` at once, with timed saves off, then the daemon is killed: every synced write must be in the bucket. Move: a branch is unmounted on one machine and mounted on the other; then it is claimed back while still mounted, and the old machine must turn read-only. Readers: a branch is mounted read-only and as a fork next to its writer.

- PASS: kill -9: nothing older than the save window (2 s) lost
- PASS: kill -9: the restarted daemon reports the unsaved changes it found
- PASS: fsync: every synced write survives `kill -9`
- PASS: planned move: every write arrives on the new machine
- PASS: takeover: every saved write arrives on the new machine
- PASS: takeover: the old machine's next save fails, so it can't overwrite the new owner
- PASS: takeover: after that, the old machine refuses writes
- PASS: takeover: the old machine reports that the branch moved
- PASS: read-only: a reader sees the saved files
- PASS: read-only: a reader cannot write
- PASS: read-only: readers do not take the branch from its writer

- PASS: fork: the forked mount starts with the files, and its writes stay in the fork
