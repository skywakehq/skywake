title: Keep data in your own bucket
icon: Database
description: Point an environment at your S3 bucket, so its indexes live there and nowhere else.

An environment can keep its data in a bucket you own. The API still runs the branches, searches and billing, but every byte of the environment's indexes is written to your bucket, one folder per index:

```
s3://acme-data/skywake/
  ix/ix_…/   an index: refs/, objects/, chunks/, blobs/, …
```

Each folder says what it holds in a small `skywake.json`, and garbage collection refuses any folder that isn't an index.

## Choose the bucket before you make anything

An environment's bucket can be set, changed or removed only while the environment holds no indexes, and no folders still waiting to be deleted. Set it right after you create the environment.

The example creates the environment `prod` and asks what a role must trust (step 1 below). Setting the bucket has no v2 route, SDK call or CLI command yet, so these steps use `/v1`, which goes away one release after v2. On your own server, `principal` is `null` until you set `SKYWAKE_API_BYOB_PRINCIPAL` to the role the API runs as.

## With an AWS role (recommended)

Skywake assumes a role in your account, so no long-lived key leaves it.

1. Ask what the role must trust:

   ```bash norun
   curl -H "authorization: Bearer $SKYWAKE_API_KEY" $SKYWAKE_URL/v1/environments/prod/store/trust
   # {"principal": "arn:aws:iam::…:role/skywake-api", "externalId": "skywake-org_…"}
   ```

2. Create a role whose trust policy lets that `principal` call `sts:AssumeRole` when `sts:ExternalId` equals `externalId`. Give it `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` and `s3:AbortMultipartUpload` on `arn:aws:s3:::acme-data/skywake/*`, and `s3:ListBucket` on the bucket with the prefix `skywake/*`.

3. Point the environment at the bucket:

   ```bash norun
   curl -X PUT -H "authorization: Bearer $SKYWAKE_API_KEY" -H "content-type: application/json" \
     $SKYWAKE_URL/v1/environments/prod/store \
     -d '{"store": "s3://acme-data/skywake",
          "access": {"type": "aws_role", "roleArn": "arn:aws:iam::123456789012:role/skywake", "region": "us-east-1"}}'
   ```

The API tries the bucket before it saves anything: it writes, reads and deletes a test branch and checks the bucket supports conditional writes. A bucket that fails answers `400` and nothing changes.

## With keys, for any S3 compatible store

R2, MinIO, Google Cloud Storage (HMAC keys) and others take an access key and an endpoint:

```json
{
  "store": "s3://acme-data/skywake",
  "access": {
    "type": "keys",
    "accessKeyId": "…",
    "secretAccessKey": "…",
    "endpoint": "https://<account>.r2.cloudflarestorage.com",
    "region": "auto"
  }
}
```

The secret is sealed with the server's `SKYWAKE_API_SECRET_KEY` and never shown again. A server without that key answers `501`.

## What changes

- New indexes in the environment go to your bucket. Asking for a `region` in such an environment answers `400`.
- Destroying an index removes its folder from your bucket. The API keeps trying until it is gone, so remove the role or keys only after that.
- Cache nodes are not used for your bucket yet; each server's own disk cache still is.
