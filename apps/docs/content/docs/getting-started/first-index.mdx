The CLI tab reads the same three rows from `products.jsonl`, one JSON object per line:

```json
{ "id": 1, "text": "red running shoes", "category": "shoes", "price": 89 }
```

## Write

There is no create step. The first `upsert` makes the index `products` and works out its schema from the rows: `text` and `category` become text fields, which are searchable by keywords and filterable, and `price` becomes a number. Text fields are embedded for you, so you can search by meaning without bringing vectors. A field you add on a later upsert is added to the schema.

Each row replaces any earlier one with the same id, so you can safely run the same upsert again. In the CLI, [`upsert`](/reference/cli/upsert) reads JSON lines, CSV or Parquet, chosen by the file's extension, or stdin with `-`. To choose the schema up front, see [create an index](../indexes/create.mdx).

## Query

`query("shoes for running")` searches by meaning and keywords together and merges the results. Each hit is the row's fields plus its `id` and `score`. The other options:

- `filter` keeps only matching rows: `{ price: { lt: 100 } }` in the SDKs, `--filter "price < 100"` in the CLI. See [filters](../indexes/filters.mdx).
- `limit` sets how many hits you get back (10 by default).
- `mode` is `"auto"` (the default), `"meaning"` or `"keywords"`.
- `sort` orders by a field instead of by score.

Add `--json` to any CLI command to print JSON.

## Fork

`fork("draft")` makes a branch of the index and copies no data. Writes to `draft` stay on the fork, and `main` never sees them until `mergeInto("main")`, or `skywake merge products@draft`. Query a branch through its handle, or as `products@draft` in the CLI. See [time travel and branches](../indexes/time-travel.mdx).
