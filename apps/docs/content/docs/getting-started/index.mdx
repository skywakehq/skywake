---
title: What is Skywake
icon: Sparkles
description: An open-source search index for vector and full-text search, kept in your own bucket.
---

Skywake is a search index. You write rows to it and search them by meaning, by keywords, or both, with filters, sorting and aggregations. Every byte of an index lives in object storage, such as an S3 bucket you own. The servers hold only caches, which you can throw away at any time.

You get an index by its name, such as `products`, and call a few verbs on it: `upsert`, `query`, `get`, `delete`, `count` and `aggregate`. The first write creates the index and works out its schema from the rows.

## What a query can do

- **Vector search.** Text fields are embedded for you, or you bring your own vectors. See [search by vector](../indexes/vector.mdx).
- **Full-text search.** BM25 over every text field, with languages, stopwords and phrases. See [full-text search](../indexes/full-text.mdx).
- **Hybrid.** A string query searches by meaning and keywords together and merges the results. See [hybrid search](../indexes/hybrid.mdx).
- **Filters and sorting.** Keep only matching rows, or order by a field instead of by score. See [filters](../indexes/filters.mdx).
- **Aggregations.** Count, sum, average, minimum and maximum, overall or by group. See [aggregations](../indexes/aggregations.mdx).

## Branches and versions

Every index starts with a `main` branch. Forking a branch copies no data, however big the index is. Writes to a fork stay there until you merge it back, so you can try a reindex or a bulk delete without touching `main`. Every write makes a new version, and you can read, fork from or restore an older one. See [time travel and branches](../indexes/time-travel.mdx).

## Environments and keys

An organization has environments, such as `prod`, `staging` and `dev`. Each is a separate set of indexes and keys, so `products` in `prod` and `products` in `staging` are different indexes. A key belongs to one environment, so a name alone says which index you mean. See [install](./install.mdx) to sign in.

## How it sits on object storage

Object storage is the source of truth. Each write is stored as a segment, and it is durable by the time the call returns. A background build groups rows into clusters, so a search by meaning reads a few clusters instead of every row. Rows written since the last build are searched exactly, so a query sees every write that finished before it.

- Branch heads are the only objects that ever change. Moving a head is a conditional write (`If-Match`), so when two writers race, exactly one of them wins.
- Any object storage with conditional writes works, such as AWS S3, Cloudflare R2 or RustFS.
- API servers read through a memory cache, a local disk cache and, when you run them, shared cache nodes.

## The pieces

| Piece        | What it does                                                                              |
| ------------ | ----------------------------------------------------------------------------------------- |
| API          | Indexes, queries, organizations, environments and keys. Postgres holds the control plane. |
| Console      | The web app: sign-in, indexes, API keys, usage.                                           |
| `skywake`    | The CLI: indexes, branches, keys, `skywake deploy` to run your own, and `skywake mcp`.    |
| SDKs and MCP | Clients for the API in seven languages, and an MCP server.                                |
