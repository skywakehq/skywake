Some retrieval models don't give one dense vector per row. SPLADE-style models give a sparse vector, and ColBERT-style models give one vector per token. Skywake can store both and score rows with them.

v2 has none of this yet: a v2 row can't hold a sparse vector or a list of vectors, and `query` has no score expression. Until it does, use the `/v1` routes below. `/v1` goes away one release after v2. In the default environment an index's `/v1` name is just its name; elsewhere it is `<environment>/<name>`.

The example makes an index with a `sparse` field and a `vectors` field, writes two rows, and scores them both ways. `rank` scores every row that passes its `filter`, exactly, and returns them best first. Rows that score 0 are left out.

## Field types

| Type      | Value                                | Produced by          |
| --------- | ------------------------------------ | -------------------- |
| `sparse`  | `{"indices": [..], "values": [..]}`  | Models like SPLADE.  |
| `vectors` | A list of vectors, all of one length | Models like ColBERT. |

You can only score these fields. They can't be filtered, sorted or [grouped](./aggregations.mdx). An index still needs a `text` field or a vector field besides them.

## Sparse: dot product

`{"dot": {"attribute", "indices", "values"}}` is the dot product of the query's sparse vector with the row's. Each entry in `indices` pairs with the entry at the same place in `values`.

## Late interaction: MaxSim

`{"max_sim": {"attribute", "vectors"}}` takes each query vector, finds its best dot product with any one of the row's vectors, and adds up those best values.

## Request

| Field     | Default | Meaning                                                      |
| --------- | ------- | ------------------------------------------------------------ |
| `score`   |         | What to rank by: `dot`, `max_sim`, or an expression of them. |
| `topK`    | `10`    | Hits to return, up to 1000.                                  |
| `offset`  | `0`     | Hits to skip, up to 10,000.                                  |
| `filter`  |         | Only rows that pass are scored.                              |
| `include` |         | Fields to return with each hit.                              |

`score` can combine `dot` and `max_sim` with numbers, number fields (`{"attribute": "stars"}`), `sum`, `product`, `max`, `min`, `decay` and `saturate`. The same expressions work as `rank` in a `/v1` [hybrid](./hybrid.mdx#weights-and-score-expressions) request, where they score only the hits its searches found.

<Callout type="info">
  `rank` reads every row that passes the filter. Narrow it with a filter on a large index.
</Callout>
