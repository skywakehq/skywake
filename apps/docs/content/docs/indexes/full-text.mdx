Use keyword search when your users type words and expect the rows that contain them. Rows are scored with BM25 over every `text` field. A string query does this already, together with search by meaning; `mode: "keywords"` runs keywords alone.

Each hit has a BM25 `score` (larger is better) and the fields you asked for. Keyword search is exact over every row, including the ones written since the last build.

## Modes

| `mode`     | Searches                                                                               |
| ---------- | -------------------------------------------------------------------------------------- |
| `auto`     | Meaning and keywords together, merged. Keywords alone when the index has no embedding. |
| `meaning`  | Meaning only. An error when the index has no embedding.                                |
| `keywords` | Keywords only, with BM25 over every `text` field.                                      |

An index made with `embed: false` (`--no-embed` in the CLI), or one whose rows bring their own vectors, has no embedding, so `auto` searches by keywords. To merge keywords with your own vectors, see [hybrid search](./hybrid.mdx).

## How text is analyzed

A `text` value is turned into a list of words in these steps:

1. The text is split into words at anything that is not a letter or a digit.
2. Words longer than `max_token_length` bytes (39 by default) are dropped.
3. Each word is lowercased, unless the field is `case_sensitive`.
4. Accents are folded, if the field sets `ascii_folding`.
5. Stopwords are dropped, if the field asks for it.
6. The remaining words are stemmed in the field's `language`, unless it sets `stemming: false`.

A `pre_tokenized` field skips these steps: its value is a list of strings, and each string is kept as one word. The query is analyzed the same way as the field. You set these in the [schema](./schemas.mdx#text-options); a text field worked out from your rows uses the defaults.

### Languages

A field's `language` can be `english` (the default), `arabic`, `danish`, `dutch`, `finnish`, `french`, `german`, `greek`, `hungarian`, `italian`, `norwegian`, `portuguese`, `romanian`, `russian`, `spanish`, `swedish`, `tamil`, `turkish`, or `none`, which keeps words whole.

### Stopwords

`stopwords: true` drops the language's stopwords, such as `the` and `of`. It is `false` by default, so that phrases like `to be or not to be` still match.

Only these languages have a stopword list: `english`, `danish`, `dutch`, `finnish`, `french`, `german`, `hungarian`, `italian`, `norwegian`, `portuguese`, `russian`, `spanish`, `swedish`. For any other language, `stopwords: true` is refused.

## BM25 parameters

You set `k1` (term saturation, default `1.2`) and `b` (length normalization, default `0.75`) for each `text` field in the schema.

## Text filters

With `mode: "keywords"`, a filter can match a `text` field on the words it contains:

| Op                    | Matches when the text has                    |
| --------------------- | -------------------------------------------- |
| `phrase`              | These words, in order.                       |
| `prefix`              | These words in order, the last one a prefix. |
| `contains_all_tokens` | Every word, anywhere.                        |
| `contains_any_token`  | At least one word.                           |

```json
{
  "and": [{ "body": { "phrase": "new password" } }, { "title": { "contains_any_token": "reset" } }]
}
```

Text filters work only at the top level of the filter or inside `and`, not under `or` or `not`. Their words are analyzed the same way as the field. In `auto` and `meaning` modes they are refused, because a search by meaning can't match words.

## Highlights, boosts, fuzzy matching and prefixes

v2 `query` has no highlights, per-field boosts, per-query `k1` and `b`, fuzzy matching or search-as-you-type yet. The `/v1` search route has them, and goes away one release after v2:

<include lang="bash" meta='tab="HTTP"'>

</include>

- `fuzzy: 1` also matches words one edit away, and `fuzzy: 2` two. An edit is a letter added, removed or changed, or two letters swapped.
- `lastAsPrefix: true` lets the last word also match longer words that start with it, so `"red sho"` finds `red shoes`.
- `boosts` weighs fields, from 0 to 1000 each.
- `highlight` returns, for each field named, about 200 characters around the best match as `text`, and the `[start, end)` position of each matched word as `marks`, counted in UTF-16 code units.
