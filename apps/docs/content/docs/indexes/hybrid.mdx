You don't call a separate method for hybrid search. A query with text already searches by meaning and by keywords, and merges the two lists into one. Set `mode` when you want only one of them.

## Modes

| `mode`           | What runs                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------- |
| `auto` (default) | Meaning and keywords together, merged. Keywords alone when the index has no embedding model. |
| `meaning`        | Only the [embedding](./embeddings-and-rerank.mdx) of your text against the rows' vectors.    |
| `keywords`       | Only BM25 over the index's `text` fields.                                                    |

`meaning` fails with `InvalidRequest` on an index that has no embedding model. A query with `vector` instead of text always searches by meaning, and a query with neither lists rows in `sort` order.

## How the lists are merged

In `auto`, each side looks at least 50 rows deep (more if `limit` is larger). The two lists are merged by reciprocal rank: a row's `score` is the sum of `1 / (60 + rank)` over the lists that found it, with ranks starting at 1. Rows that both sides found usually rank first.

The [`filter`](./filters.mdx) applies to both sides, and both see the same rows. `fields` picks which fields come back, as in any query.

## Weights and score expressions

v2 has no setting for per-side weights or your own score expression. Until it does, the `/v1` `hybrid` route takes named searches, weights and a `rank` expression. `/v1` goes away one release after v2.
