To add or replace rows, upsert them. Pass one row or a list. Each row is flat: an `id` and its fields.

- A row replaces any earlier row with the same id. A row with no `id` gets a random UUID, and `upsert` returns the `ids` it wrote.
- The first upsert creates the index, and a new field is added to its [schema](./schemas.mdx#inferred-types).
- A write is [durable by the time the call returns](./consistency-and-limits.mdx), and the next query sees it.
- Any number of rows works. The SDKs send them in requests of up to 10,000 rows and 24 MiB. `POST /v2/indexes/{index}/rows` takes up to 10,000 rows.
- The CLI reads JSON lines, CSV or Parquet, from a file or from `-` for stdin.
- Pass `{ branch }` to the handle, or `NAME@BRANCH` in the CLI, to write to a branch other than `main`.

## Ids

An id is a string of 1 to 256 characters or a whole number from 0, or a UUID when the schema's `id` is `uuid`. Number ids sort before string ids. In the CLI and in URLs, an id made only of digits is read as a number first.

## Update and delete

`update` changes some fields and keeps the rest. Set a field to `null` to remove it. `delete` removes rows. Both take an id, a list of ids, or a [filter](./filters.mdx), and return how many rows they changed.

- A filter can be passed as it is, as in `update({ stock: 0 }, ...)`, or wrapped as `{ filter }`.
- Updating or deleting an id that doesn't exist does nothing.
- `get(id)` returns the row, or `null` when there is none. Vectors don't come back.
- The CLI deletes by id: `skywake delete products 4 5`.

## Read every row

`rows()` goes through every row of a branch, in id order, a page at a time. Use it for exports and backfills, and keep it off hot paths. Pass a filter to read only the rows that match.

## Conditional writes

A conditional write only applies if the stored row is in a certain state, for example to avoid overwriting newer data. v2 has no conditional write yet. The `/v1` write route has one, and goes away one release after v2. A condition is a filter checked against each row as it was before the write, and `{"$ref_new": "field"}` means that field of the row being written. ## Errors

| Error             | When                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------ |
| `InvalidRequest`  | A field doesn't fit the schema. The error names it, such as `rows[0].price`.         |
| `PermissionError` | The index is read-only, or the key may not write to it.                              |
| `NotFound`        | The branch doesn't exist. Only an upsert to `main` creates an index.                 |
| `RateLimited`     | Too many rows are waiting to be stored or built on the branch. The SDKs retry first. |
