A write is durable by the time the call returns, and every read sees every write that finished before it. You don't wait for a build or set anything: the next `query`, `get`, `count` or `aggregate` sees the change.

</include>

Rows written since the last build are searched exactly until the next build puts them in the clusters, so new rows are found straight away.

## How reads stay fresh

A server that reads an index often takes a short read lease on it. While it holds the lease, every write on any server tells it about the change before the write returns, so it can reuse what it read last and a read of a warm index makes no request to Postgres or object storage. If a write can't reach a lease holder, it revokes the lease and waits until it is over (at most about 11 seconds), so a read never sees an old snapshot.

When you run Skywake yourself, leases need `SKYWAKE_API_PEER_TOKEN`, a secret the API servers share to reach each other. Without it, each read asks object storage for the branch head, which costs about one round trip.

Servers also cache keys and index settings for up to 30 seconds, and Postgres tells every server as soon as one changes. A revoked key stops working right away. Servers get these updates through `LISTEN`, so connect them to Postgres directly or through a pooler in session mode, not transaction mode.

## Many reads on one snapshot

v2 has no call that runs several reads on one snapshot, and no `eventual` reads. Until it does, the `/v1` `multi` route runs up to 16 `query`, `search`, `hybrid`, `order`, `rank` or `aggregate` requests that all see the same snapshot. `/v1` goes away one release after v2. In the default environment an index's `/v1` name is just its name; elsewhere it is `<environment>/<name>`.

## Limits

| Limit                                          | Value                          |
| ---------------------------------------------- | ------------------------------ |
| Rows per `upsert` in the SDKs and CLI          | any; they send them in batches |
| Rows per HTTP upsert request                   | 10,000                         |
| Bytes per HTTP request                         | 32 MiB                         |
| Ids per `update` or `delete`                   | 10,000                         |
| Numbers per vector                             | 4096                           |
| Vector fields per index                        | 8                              |
| Fields per index                               | 64                             |
| Field name                                     | 64 characters                  |
| String id                                      | 256 characters                 |
| Index name                                     | 100 characters, no `/`         |
| Branch name                                    | 200 characters                 |
| Query `limit`                                  | 1000 (10 by default)           |
| Query text                                     | 4096 characters                |
| `fields` asked for                             | 64                             |
| Text embedded per field                        | 32,768 characters              |
| `groupBy` fields                               | 8                              |
| Groups returned                                | 1000                           |
| Items per page of a list (`rows`, `versions`…) | 1000 (100 by default)          |

## Errors

Every error has a `code`, a `message`, a `hint` that says how to fix it when there is one, and a `requestId`. The SDKs raise one class per kind, the same in every language:

| Class             | HTTP  | When                                                                       |
| ----------------- | ----- | -------------------------------------------------------------------------- |
| `AuthError`       | `401` | No key, a bad key, or an expired key.                                      |
| `PermissionError` | `403` | The key's role or environment doesn't allow it, or the index is read-only. |
| `NotFound`        | `404` | No such index, branch or row. `hint` suggests the closest name.            |
| `Conflict`        | `409` | A write lost a race, or a name is taken.                                   |
| `InvalidRequest`  | `400` | A field doesn't fit the schema, or a bad option. The message names it.     |
| `RateLimited`     | `429` | Still limited after retrying, such as too many rows waiting on a branch.   |
| `ServerError`     | `5xx` | Our side, such as an embedding provider that failed. Retried first.        |

Over HTTP the body is `{ "error": { "code", "message", "hint", "request_id" } }`. The SDKs retry only requests that are safe to retry.
