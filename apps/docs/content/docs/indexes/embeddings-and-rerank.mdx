description: How rows are embedded for search by meaning, how to bring your own vectors, and where rerank stands in v2.

You don't have to compute embeddings. When you upsert rows with text, Skywake embeds them with the environment's embedding model, and `query("words")` searches them by meaning. You can also bring your own vectors, or turn embedding off.

## Automatic embeddings

The first upsert to a new index picks one text field to embed: the first of `text`, `content`, `body`, `description`, `title` and `name` that the rows have, or else their first string field. Each row's value of that field is embedded into a vector that you never see or get back. The other string fields are still searched by keywords.

- The environment's model is used unless you choose one when you make the index.
- Changing the embedded field on an upsert embeds it again. Each text embedded is billed as an embedding.
- With no embedding model in the environment, an index searches by keywords only.

To choose the model, or to turn embedding off, make the index first with `embed` and a schema:

<include lang="ts" meta='tab="TypeScript"'>
  ../../../examples/indexes-2/keywords-only.ts
</include>

`embed: { model: "openai/text-embedding-3-small" }` picks a model from the [list below](#models); `embed: false` makes a keywords-only index.

## Your own vectors

A field that holds a list of numbers is a vector field, and its length is the dimension. An index with a vector field is not embedded for you; query it with `vector`.

<include lang="ts" meta='tab="TypeScript"'>
  ../../../examples/indexes-2/own-vectors.ts
</include>

<include lang="py" meta='tab="Python"'>
  ../../../examples/indexes-2/own-vectors.py
</include>

Every row's vector must have the same length. Vector fields are set when the index is made: a new vector field on a later upsert fails with `InvalidRequest`. To change them, make a new index.

v2 has no way to embed images; send image vectors you computed yourself.

## Rerank

v2 has no rerank option on `query` yet. The `/v1` `query`, `search` and `hybrid` routes take `rerank`, which sends the hits to a rerank model and orders them again, best first. `/v1` goes away one release after v2. In the default environment an index's `/v1` name is just its name; elsewhere it is `<environment>/<name>`.

```json title="POST /v1/indexes/articles/branches/main/search"
{
  "query": "reset password",
  "fields": ["text"],
  "topK": 50,
  "rerank": { "model": "cohere/rerank-v3.5", "field": "text", "topN": 5 }
}
```

| Field   | Default      | Meaning                                         |
| ------- | ------------ | ----------------------------------------------- |
| `model` |              | The rerank model, such as `cohere/rerank-v3.5`. |
| `field` |              | The text field whose value is ranked.           |
| `query` | the search's | What to rank by.                                |
| `topN`  | every hit    | The most hits to return after reranking.        |

The server needs a rerank provider for this (below). Each reranked request is billed as a rerank.

## Models

The server knows these models by name. Any other name is sent to the default provider as written.

| Model                                                                                               | Numbers per vector |
| --------------------------------------------------------------------------------------------------- | ------------------ |
| `openai/text-embedding-3-small`                                                                     | 1536               |
| `openai/text-embedding-3-large`                                                                     | 3072               |
| `cohere/embed-v4.0`                                                                                 | 1536               |
| `google/gemini-embedding-2`                                                                         | 1536               |
| `voyage/voyage-4`, `-4-large`, `-4-lite`, `-4-nano`, `voyage/voyage-code-3`, `voyage/voyage-code-4` | 1024               |
| `qwen/qwen3-embedding-0p6b`, `qwen/qwen3-embedding-4b`, `qwen/qwen3-embedding-8b`                   | 1024               |
| `nvidia/nemotron-3-embed-1b`, `nvidia/nemotron-3.5-embed-1b`                                        | 2048               |
| `nvidia/nemotron-3-embed-8b`, `nvidia/nemotron-3.5-embed-8b`                                        | 4096               |
| `baai/bge-m3`                                                                                       | 1024               |
| `zeroentropy/zembed-1`                                                                              | 1280               |

Rerank models: `cohere/rerank-v3.5`, `voyage/rerank-3`, `voyage/rerank-3-lite`, `zeroentropy/zerank-2`. The full list is `EMBEDDING_MODELS` and `RERANK_MODELS` in `@skywake/contract`.

## Providers

When you run Skywake yourself, the server sends each model to a provider set with [environment variables](../self-hosting/docker-compose.mdx). A request that needs a provider that isn't set fails with `InvalidRequest`; one whose provider can't be reached fails with `ServerError`.

| Variable                                           | Provider                                                                                                                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SKYWAKE_API_PROVIDERS`                            | Keys for the catalog's vendors, as JSON: `{"openai": {"key": "sk-.."}}`. `url` and `rerank_url` point a vendor elsewhere, such as your own server for `baai`. |
| `SKYWAKE_API_EMBED_URL`, `SKYWAKE_API_EMBED_KEY`   | The default: OpenAI-style `POST /embeddings`. Gateways such as LiteLLM or OpenRouter work here.                                                               |
| `SKYWAKE_API_RERANK_URL`, `SKYWAKE_API_RERANK_KEY` | The default rerank provider: Cohere-style `POST /rerank`. Cohere, Jina and Voyage responses are read.                                                         |

Without their own URL, `baai` and `qwen` models go to DeepInfra. `zeroentropy` models always need their own URL.
