You don't have to compute embeddings yourself. Name a model on a vector column, and you can send text or images where a vector goes; the server turns them into vectors. You can also ask the server to reorder your hits with a rerank model.

```ts tab="TypeScript"
const docs = await sky.indexes.create("docs", {
  vectors: [{ name: "embedding", dims: 1536, embed: { model: "openai/text-embedding-3-small" } }],
  attributes: [{ name: "body", type: "string" }],
});
await docs.upsert([
  { id: 1, vectors: { embedding: "a cat sleeps" }, attributes: { body: "a cat sleeps" } },
]);
const hits = await docs.query({
  vector: { column: "embedding", value: "kitten" },
  topK: 50,
  rerank: { model: "cohere/rerank-v3.5", field: "body", topN: 5 },
});
```

```py tab="Python"
docs = sky.indexes.create(
    "docs",
    vectors=[{"name": "embedding", "dims": 1536, "embed": {"model": "openai/text-embedding-3-small"}}],
    attributes=[{"name": "body", "type": "string"}],
)
docs.upsert([{"id": 1, "vectors": {"embedding": "a cat sleeps"}, "attributes": {"body": "a cat sleeps"}}])
hits = docs.query("embedding", "kitten", top_k=50, rerank={"model": "cohere/rerank-v3.5", "field": "body", "topN": 5})
```

## Embeddings

A [vector column](./schemas.mdx#vector-columns) with `embed: {model}` takes text or an image anywhere it takes a vector: in documents, in [`query`](./vector.mdx), and in [hybrid](./hybrid.mdx) vector searches. The server embeds the value with `model`, and the model must return `dims` numbers. If you use a [catalog model](#models), this is checked when you create the column: `dims` must be one of the model's sizes.

Such a column accepts three kinds of value:

- `[0.1, 0.2, ..]`: a vector, as usual.
- `"a cat sleeps"`: text to embed, up to 32,768 characters.
- `{"image": "https://..."}`: an image to embed, given as an https URL or a base64 `data:image/...` URL, up to 8 MiB. The model must accept images.

With `embed: {model, from: "body"}`, a document that has no vector for the column gets one from its `body` attribute, which must be a `string` or `text`. A patch can't change `body`, because the vector would then be out of date. Upsert the whole document instead.

A column without `embed` takes only numbers. The server checks the whole request before it calls the provider. Each text or image it embeds counts in [`billing.embeddings`](./consistency-and-limits.mdx#performance-and-billing).

## Rerank

Use `rerank` when the search finds the right documents but you want a model to decide their order. It sends the hits to a rerank model on the server's rerank provider, orders them again best first, and gives each one a `rerank_score` (larger is better). It works on `query`, [`search`](./full-text.mdx) and `hybrid`.

| Field   | Type                           | Default   | Meaning                                         |
| ------- | ------------------------------ | --------- | ----------------------------------------------- |
| `model` | string                         |           | The rerank model, such as `cohere/rerank-v3.5`. |
| `field` | a `string` or `text` attribute |           | Whose value is ranked against `query`.          |
| `query` | string, up to 4096 chars       | see below | What to rank by.                                |
| `topN`  | int, 1 to 1000                 | every hit | The most hits to return after reranking.        |

If you leave out `query`, the server picks one:

- In `search`, it uses the search's text.
- In `query`, it uses the vector's text. A vector given as numbers has no text, so you must set `query`.
- In `hybrid`, it uses the text of the first text search. If there is none, it uses the first vector given as text.

The model reads the `field` of each hit the search returns, so `topK` sets how many hits it sees. The field stays in the hit's attributes if you list it in `include`, or if you set `exclude` and it is not in that list. A hybrid reranks the fused hits. A search inside `searches` can't set its own `rerank`.

Each reranked request counts in `billing.reranks`.

## Models

The server knows these models by name. Any other model name is sent to the default provider exactly as you wrote it.

| Model                                                                                               | Numbers per vector | Sizes you can ask for             |
| --------------------------------------------------------------------------------------------------- | ------------------ | --------------------------------- |
| `openai/text-embedding-3-small`                                                                     | 1536               | 1536                              |
| `openai/text-embedding-3-large`                                                                     | 3072               | 3072                              |
| `cohere/embed-v4.0`                                                                                 | 1536               | 256, 512, 1024, 1536              |
| `google/gemini-embedding-2`                                                                         | 1536               | 768, 1536, 3072                   |
| `voyage/voyage-4`, `-4-large`, `-4-lite`, `-4-nano`, `voyage/voyage-code-3`, `voyage/voyage-code-4` | 1024               | 256, 512, 1024, 2048              |
| `qwen/qwen3-embedding-0p6b`                                                                         | 1024               | 256, 384, 512, 768, 1024          |
| `qwen/qwen3-embedding-4b`                                                                           | 1024               | 512, 1024, 1536, 2048, 2560       |
| `qwen/qwen3-embedding-8b`                                                                           | 1024               | 512, 1024, 1536, 2048, 3072, 4096 |

## Providers

The server sends each model to a provider, which you set with [environment variables](../self-hosting/docker-compose.mdx#optional). If the provider a request needs is not set, the request fails with `400`.

| Variable                                           | Provider                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SKYWAKE_API_PROVIDERS`                            | Keys for the catalog's vendors, as JSON: `{"openai": {"key": "sk-.."}, "voyage": {"key": ".."}}`. A vendor's model goes to that vendor under the vendor's own name, and a smaller size is asked for with the vendor's own field. `url` and `rerank_url` point a vendor elsewhere, such as your own server for `baai`. |
| `SKYWAKE_API_EMBED_URL`, `SKYWAKE_API_EMBED_KEY`   | The default: OpenAI-style `POST /embeddings`. It gets every other model by its full name, so a gateway such as LiteLLM or OpenRouter works here.                                                                                                                                                                      |
| `SKYWAKE_API_RERANK_URL`, `SKYWAKE_API_RERANK_KEY` | The default rerank provider: Cohere-style `POST /rerank`. Responses in the Cohere, Jina and Voyage formats are read.                                                                                                                                                                                                                   |

If you don't give them their own URL, `baai` and `qwen` models go to DeepInfra. `zeroentropy` models always need their own URL.

If a provider can't be reached or returns a bad response, the request fails with `503`.
