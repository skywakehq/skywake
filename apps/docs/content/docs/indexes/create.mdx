You only need to create an index when you want to choose its fields, types or region yourself. Otherwise the first [upsert](./write.mdx) makes it. To create one, send a name and a [schema](./schemas.mdx):

<include lang="py" meta='tab="Python"'>

<include lang="bash" meta='tab="CLI"'>

`schema.json` holds the same schema:

```json title="schema.json"
{
  "attributes": [
    { "name": "text", "type": "text" },
    { "name": "category", "type": "string" },
    { "name": "price", "type": "number" }
  ]
}
```

The new index starts with an empty `main` branch. If the name is already taken by an index in the environment, you get a `Conflict` error.

When the environment has an embedding model and the schema has no vectors, the index gets a hidden vector, `_meaning`, made from its first `text` or `string` field. That is what lets `query("words")` search by meaning.

## Options

| Option   | Default                 | Meaning                                                                                 |
| -------- | ----------------------- | --------------------------------------------------------------------------------------- |
| `schema` |                         | The fields and vectors. Required here; see [schemas and types](./schemas.mdx).          |
| `region` | the default region      | Where the index keeps its data. Can't change later.                                     |
| `embed`  | the environment's model | `{ model }` to embed text with another model, or `false` for keywords and filters only. |

In the CLI these are `--schema FILE`, `--region`, `--embed MODEL` and `--no-embed`. You need an `admin` key to create an index, `write` to upsert, and `read` to query. See [roles](../security/api-keys.mdx).

## Create on first write

You can also skip this step. Upserting to an index that doesn't exist creates it, with a type for each field taken from its value. See [schemas and types](./schemas.mdx#inferred-types).

## Change an index

`configure` changes an index's settings. It takes effect at once on every branch, and nothing is rebuilt.

<include lang="ts" meta='tab="TypeScript"'>
  ../../../examples/indexes-1/configure.ts
</include>

<include lang="py" meta='tab="Python"'>
  ../../../examples/indexes-1/configure.py
</include>

| Setting          | Type                       | Meaning                                                                                                              |
| ---------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `attributes`     | list                       | Fields to add. A field the index has keeps its type, but can turn on `filter_index`. Older rows don't have new ones. |
| `dropAttributes` | list of names              | Fields to remove, with their values. Refused while the index has more than one branch.                               |
| `readOnly`       | bool                       | While this is true, writes are refused.                                                                              |
| `retentionDays`  | int, 0 to 36500, or `null` | How long replaced versions are kept. `null` keeps all of them. See [time travel](./time-travel.mdx).                 |

Python takes the same settings as `read_only`, `retention_days`, `drop_attributes` and so on. Over HTTP it is `PATCH /v2/indexes/{index}`.

## List, inspect, copy and destroy

<include lang="ts" meta='tab="TypeScript"'>
  ../../../examples/indexes-1/manage.ts
</include>

<include lang="py" meta='tab="Python"'>
  ../../../examples/indexes-1/manage.py
</include>

<include lang="bash" meta='tab="CLI"'>
  ../../../examples/indexes-1/manage.sh
</include>

| Task                       | TypeScript            | Python                | CLI                          | HTTP                            |
| -------------------------- | --------------------- | --------------------- | ---------------------------- | ------------------------------- |
| Every index                | `sky.listIndexes()`   | `sky.list_indexes()`  | `skywake indexes`            | `GET /v2/indexes`               |
| Schema, rows and branches  | `products.info()`     | `products.info()`     |                              | `GET /v2/indexes/{index}`       |
| Copy to a new index        | `products.copy(name)` | `products.copy(name)` |                              | `POST /v2/indexes/{index}/copy` |
| Destroy, with every branch | `products.destroy()`  | `products.destroy()`  | `skywake destroy NAME --yes` | `DELETE /v2/indexes/{index}`    |

`info()` returns the `name`, `region`, `schema`, `rows`, `bytes`, `read_only`, `retention_days` and the names of its `branches`.

A copy is a separate index whose `main` starts as this branch, with the same schema. After that, writes to one never reach the other. Pass `environment` to make the copy in another environment, with a key that can reach both.
