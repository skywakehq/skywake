Branches let you try changes on an index without touching the rows everyone else reads. Fork a branch, write to it, and merge it back when you want to keep the changes. Every change is kept as a version, so you can also go back to how the index was.

Every index starts with a `main` branch. A branch is a line of versions, and every write to it makes a new version.

## Fork

`fork(name)` makes a branch from the handle's branch and returns a handle to it. Nothing is copied, at any size. After the fork, each branch sees only its own writes.

To work on a branch that already exists, get a handle with `sky.index("products", { branch: "draft" })` (Python: `sky.index("products", branch="draft")`). In the CLI, write `products@draft`. Every read and write takes the branch this way; no branch means `main`.

## Merge

`mergeInto("main")` (Python: `merge_into`) brings the fork's changes into another branch. It takes the writes the fork made since it was forked, or since it was last merged there, and returns `{ rows }`, the number of rows and deletes it brought in.

- If both branches wrote the same row, the fork's write wins. Merging an index never stops on a conflict.
- Fields the fork added come along too.
- `destroy()` on the fork's handle deletes the branch. You can't destroy `main` this way: `destroy()` on `main` deletes the whole index.

`branches()` lists every branch with the branch it was forked from.

- `versions()` lists the branch's versions, newest first: `{ id, created, rows }`. The CLI shows them with `skywake log`.
- `fork(name, { at })` forks an older version instead of the newest one. Use it to read the index as it was, without touching `main`.
- `restore(versionOrTime)` makes the branch look like it did then. It takes a version id or a time (a `Date` in TypeScript, a `datetime` in Python, or a string such as `2026-11-01T12:00:00Z`). It adds a new version, so nothing is lost and you can restore again.

<Callout type="info">
  v2 has no `at` on index queries yet. To query the past, fork at the version and query the fork.
</Callout>

## Retention

`retentionDays` sets how long a replaced version can still be restored. By default every version is kept. Set it with `configure({ retentionDays: 30 })` (Python: `configure(retention_days=30)`).

Deleting the data no version needs any more is a `/v1` call with no v2 version yet; `/v1` goes away one release after v2. It keeps every branch, every version replaced within `retention_days`, and anything younger than eight days. It returns an operation that runs in the background.
