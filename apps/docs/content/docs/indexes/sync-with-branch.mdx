---
title: Keep an index in step with a branch
icon: RefreshCw
description: Link an index to a namespace, so its files are searchable and every fork has its own index.
---

If your agents search the files on a branch, the index must match those files. Link an index to the namespace and Skywake keeps it in step: `main` from the moment you link, and every branch you fork `withIndex`.

```ts
import { Skywake } from "@skywake/sdk";

const sky = new Skywake({ url: process.env.SKYWAKE_URL!, key: process.env.SKYWAKE_KEY! });
const app = sky.namespace("team/app");

await app.linkIndex("team/app-files", {
  include: ["src/**", "docs/**"],
  exclude: ["**/*.lock"],
});

const hits = await sky.index("team/app-files").search({ query: "retry backoff" });
// each hit's id is the file's path; `path` and `text` are its attributes
```

The index is made when it does not exist, with a `path` string and a `text` attribute searched by BM25. An existing index works if it has both. Linking is opt-in: a namespace without a link is never indexed, and an index used on its own is unchanged.

## What gets indexed, and when

- Files that match `include` (all when empty) and none of `exclude`, at most `maxBytes` (1 MiB by default), and valid UTF-8 text. Others are left out.
- A commit is searchable within seconds. A save, such as a mount's autosave, waits about 30 seconds, so a burst of saves is indexed once.
- Saves written straight to the bucket, by a mount or the CLI with `skywake://` credentials, are found too: they can call `advanced` to be indexed sooner, and every linked branch is checked at least every 5 minutes either way.
- Each sync writes only what changed between the commit the index matches and the branch's head. Removing a folder removes the documents of everything in it.

Give `embed: {model, dims}` when the link makes the index to also embed each file's first 8,000 characters for vector search. Embeddings are billed as usual.

## Forks

Fork a branch `withIndex` and its index forks with it:

```ts
const main = app.branch("main");
const agent = await main.fork("agents/42", undefined, { withIndex: true });
const found = await sky.index("team/app-files").at("agents/42").search({ query: "retry" });
```

The new index branch starts from the newest version of `main`'s index, so it is searchable at once and only what differs is indexed. What the agent writes lands only in its own index branch. Deleting the files branch deletes its index branch.

After you merge the agent's branch into `main`, `main`'s index catches up on its own: the merge moved `main`, so the difference is indexed.

## How far behind

```ts
const status = await agent.indexStatus();
// {branch, head, synced, behind, syncedAt, error, version}
```

`synced` is the commit the index matches and `version` the index version that matches it. `error` says why the last try failed, if it did; failed tries are retried with backoff.

To change the globs, link again with the new ones; the branches are indexed again in full. `unlinkIndex()` stops indexing and keeps the index.

## Doing it yourself

To control the documents yourself, skip the link and call `syncIndex` (TypeScript), which upserts the files that changed since an earlier sync and deletes the documents of removed ones:

```ts
import { syncIndex } from "@skywake/sdk";

let synced = await syncIndex(main, code); // every file, the first time
synced = await syncIndex(main, code, { since: synced.head });
```

| Option        | Default                                                                | Meaning                                                                      |
| ------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `since`       | none: every file is upserted, none deleted                             | The `head` an earlier sync returned.                                         |
| `document`    | UTF-8 files as `{id: path, attributes: {path, text}}`; others left out | Turns a file (`{path, bytes}`) into its document, or `null` to leave it out. |
| `id`          | the path                                                               | The id of a file's document, to delete it. Must match `document`.            |
| `concurrency` | `8`                                                                    | Files read at once.                                                          |
