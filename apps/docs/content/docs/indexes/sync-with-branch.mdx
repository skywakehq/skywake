To search the files on a disk, you don't make or sync an index yourself. Turn on the disk's `search` setting and call `query` on the disk. Skywake keeps the search in step with every branch.

Each hit is `{ path, score, snippet }`, best first, one per file. `query` takes `limit` (10 by default) and `path` to search one folder, and searches the handle's branch.

## Turn it on or off

`search` is on by default when the environment has an embedding model, so a disk made by its first write is usually searchable already. Set it yourself when you make the disk, or change it later:

| Do                | TypeScript                                | Python                                | CLI or HTTP                         |
| ----------------- | ----------------------------------------- | ------------------------------------- | ----------------------------------- |
| On when making it | `sky.createDisk("app", { search: true })` | `sky.create_disk("app", search=True)` | `skywake create disk app --search`  |
| Change it         | `app.configure({ search: false })`        | `app.configure(search=False)`         | `PATCH /v2/disks/app {"search": …}` |
| See it            | `(await app.info()).search`               | `app.info()["search"]`                | `GET /v2/disks/app`                 |

With search off, `query` fails with `Conflict` and a hint to turn it on. `grep` and `find` work either way. Turning search off deletes what was indexed.

The index behind a disk's search is not one of your indexes: it isn't in `listIndexes()` or `skywake indexes`, and you use it only through the disk's `query`.

## Branches

Every branch of the disk has its own search. A fork is searchable at once, and what an agent writes on its branch is found only there. After a merge, `main` catches up on its own.

## What gets indexed, and when

- Text files, PDFs, and Word, PowerPoint and Excel files (`.docx`, `.pptx`, `.xlsx`), up to 16 MiB of text each. Long files are split into passages, and a file is returned once, at its best passage.
- Binary files, old `.doc`, `.ppt` and `.xls` files, and PDFs without a text layer are skipped.
- A commit is searchable within seconds, not at once, so poll briefly in scripts as the examples do. Saves from a [mount](../filesystem/mount.mdx) are batched for about 30 seconds.
- Only what changed since the last sync is indexed again, and an edit embeds only the passages it changed. Embeddings are billed as usual.

v2 has no setting for which paths are indexed and no sync status yet: every file the rules above accept is indexed.

To search rows you shape yourself, write them to an [index](./index.mdx) instead.
