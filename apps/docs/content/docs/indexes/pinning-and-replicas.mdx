Any API server can serve any index, and opens it when a request needs it. A pinned index also gets 1 to 8 reserved servers, called its **replicas**. Each replica keeps the index open, never evicts it, and keeps everything its current version needs on local disk.

## Pin, repin, unpin

| Do               | TypeScript                               | Python                              | HTTP: `PATCH /v2/indexes/{index}` |
| ---------------- | ---------------------------------------- | ----------------------------------- | --------------------------------- |
| Pin              | `configure({ pinned: { replicas: 2 } })` | `configure(pinned={"replicas": 2})` | `{"pinned": {"replicas": 2}}`     |
| Change the count | `configure({ pinned: { replicas: 3 } })` | `configure(pinned={"replicas": 3})` | `{"pinned": {"replicas": 3}}`     |
| Unpin            | `configure({ pinned: null })`            | not yet; use HTTP                   | `{"pinned": null}`                |

The change takes effect at once, on every branch. A [copy](./create.mdx) of a pinned index is not pinned. The CLI has no command for it.

## Where it is pinned

v2's `info()` doesn't show pinning yet. `GET /v1/indexes/{index}` (the last call in the HTTP example) returns `pinned`, what you asked for, and `pinning`, what is running now. `/v1` goes away one release after v2.

```json
{
  "pinned": { "replicas": 2 },
  "pinning": {
    "replicas": [
      { "server": "api-1", "warm": true, "in_flight": 2 },
      { "server": "api-2", "warm": false, "in_flight": 0 }
    ]
  }
}
```

| Field       | Meaning                                                      |
| ----------- | ------------------------------------------------------------ |
| `server`    | The API server holding the replica.                          |
| `warm`      | Whether everything the current version needs is on its disk. |
| `in_flight` | Queries it is serving now.                                   |

If fewer servers are running than the replicas you asked for, you get fewer replicas. On a single server, `replicas` is empty.

## How queries are routed

- Reads on a pinned index (`query`, `count`, `aggregate`) go to the least busy replica. The `x-skywake-server` response header names the server that served it.
- If no replica responds, the server that got the request serves it itself.
- Whenever `main` changes, each replica warms the index again.
- Writes are not routed. Any server accepts them.

## Billing

A pinned index is billed per GB-hour for each replica instead of per query. Its queries don't count toward the bill.

## Self-hosting

Servers find each other through the database. Each server writes a heartbeat every 2 seconds, and a server seen in the last 10 seconds counts as live. Every server places each pinned index by rendezvous hashing over the live servers, so they all agree without a coordinator, and when a server joins or leaves, only the indexes placed on it move.

| Variable                 | Meaning                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `SKYWAKE_API_PEER_URL`   | How the other servers reach this one. `http://127.0.0.1:<port>` by default.                                   |
| `SKYWAKE_API_PEER_TOKEN` | Shared by every server, at least 16 characters. Without it, no server passes queries on or holds read leases. |
