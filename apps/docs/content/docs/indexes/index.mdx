A string query searches by meaning and keywords together. Each hit is the row's fields plus a `score`, where larger is better.

## What an index is

An index holds **rows**. A row is an `id` and any **fields**, such as `{ id: 1, text: "red running shoes", price: 89 }`.

- **Fields**: Each field has a type, taken from its first value or set in a [schema](./schemas.mdx). You can filter, sort and group by them, and search `text` fields by keywords.
- **Meaning**: Unless your rows carry their own vector, a `text` field is embedded with the environment's model into a vector you never see, so `query("shoes for running")` finds rows by meaning.
- **Branches**: Every index starts with a `main` branch. [Fork](./time-travel.mdx) one when you want a copy that sees only its own writes. Forking copies nothing.
- **Versions**: Every change makes a new version of the branch. You can fork from or restore an older one.

## How it sits on object storage

Object storage is the source of truth. Each write is stored as a segment, and it is durable by the time the call returns. A **build** groups the rows written so far into clusters, so that a search by meaning reads a few clusters instead of every row. Builds run in the background.

Rows written since the last build are searched exactly, so your queries see them without waiting for a build. Reads go through a memory cache and a disk cache.

Any API server can serve any index. If you want an index to stay open on reserved servers, [pin](./pinning-and-replicas.mdx) it.

## Names and environments

An index has a short name, such as `products`. A name uses letters, digits, `.`, `_` and `-`, has no `/`, and is at most 100 characters.

Your key decides the environment. A key belongs to one environment, such as `prod` or `staging`, so `sky.index("products")` with a `prod` key is the `products` index in `prod`. The same name in `staging` is a different index.

- Names are unique within an environment, across disks and indexes together.
- An all-environments key names the environment with `environment` in the SDKs, `SKYWAKE_ENV` or `--env` in the CLI, or the `Skywake-Environment` header over HTTP.
- A key may be narrowed to some indexes, such as `only: ["products", "docs-*"]`. What it can do depends on its [role](../security/api-keys.mdx): `read` to query, `write` to upsert, `admin` to create and destroy.
- Each index picks its region when it is made, and it can't move later.
