Use an aggregation when you want numbers about your rows instead of the rows, such as how many there are per tag or what their prices add up to.

The result is one entry per group:

```json
[
  { "group": { "tag": "shoes" }, "count": 2, "sum": { "price": 209 }, "min": { "price": 89 } },
  { "group": { "tag": "socks" }, "count": 1, "sum": { "price": 12 }, "min": { "price": 12 } }
]
```

The CLI has no aggregate command; use an SDK or `POST /v2/indexes/{index}/aggregate`.

## Options

| Option                     | Type                    | Default   | Meaning                                               |
| -------------------------- | ----------------------- | --------- | ----------------------------------------------------- |
| `groupBy`                  | a field or up to 8      | one group | A group per set of values of these fields.            |
| `count`                    | boolean                 | `true`    | Count the rows in each group.                         |
| `sum`, `avg`, `min`, `max` | a field or a list       |           | Measure these number fields. Each comes back by name. |
| `filter`                   | [filter](./filters.mdx) |           | Only rows that pass are measured.                     |
| `branch`                   | string                  | `main`    | The [branch](./time-travel.mdx) to read.              |

For the number of rows alone, `count({ filter })` returns a number.

## Groups

- `groupBy` takes fields that hold one value: numbers, bools and `text` fields. Not lists or vectors.
- Groups come back sorted by their values, at most 1000 of them.
- A group's `group` holds the values its rows share. A field the rows don't have is left out of it.
- With no `groupBy`, there is one group, and its `group` is `{}`.
